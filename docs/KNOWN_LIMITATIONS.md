# القيود والمخاطر المعروفة

## 1. النشر الخارجي غير منفذ

لا توجد صلاحيات أو أدلة على نشر عام أو DNS أو شهادة TLS. لذلك لا يمكن تأكيد HTTPS العام أو الوصول من خارج الشبكة أو فهرسة محركات البحث. هذه ليست مشكلة كود محلية، لكنها تمنع اعتماد نشر production.

## 2. تدقيق npm

`npm audit --omit=dev` أظهر **تنبيهين بدرجة moderate**:

- المسار: `next@16.2.10` يتضمن PostCSS أقدم من `8.5.10`.
- المرجع: GHSA-qx2v-qp2m-jg93، يتعلق بتمرير CSS غير موثوق يحوي `</style>` إلى CSS stringify.
- التحقق من npm في يوم التنفيذ أكد أن `16.2.10` هو أحدث إصدار مستقر من Next.
- `npm audit fix --force` يقترح تثبيت `next@9.3.3`، وهو تغيير كاسر/تراجع غير آمن، لذلك لم ينفذ.

التطبيق الحالي لا يستقبل CSS من مستخدمين أو CMS ولا يصنع CSS من مدخلات عامة، ما يخفض قابلية الاستغلال العملية، لكنه لا يساوي نتيجة audit صفرية. يلزم قبول المخاطر من مالك الأمن أو حل upstream قبل سياسة إطلاق تتطلب صفراً من التحذيرات.

## 3. محتوى وبيانات مستقبلية

النماذج لا ترسل، ولا توجد تحليلات أو مدفوعات أو حسابات أو أخبار أو معرض مفعّل. أي تفعيل جديد يحتاج backend، خصوصية، أمن، مراقبة وموافقة محتوى منفصلة.

## 4. قياس الأداء والإتاحة

تمت اختبارات Chrome محلية بنجاح، لكن لا توجد شهادة WCAG ولا قياس Core Web Vitals ميداني ولا اختبار أجهزة حقيقية متعددة. هذه عناصر ما بعد النشر/القبول اليدوي.
